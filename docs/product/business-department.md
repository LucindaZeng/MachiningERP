# 业务部功能、权限、预警与报表矩阵

本文补齐 [十部门功能矩阵](department-control-matrix.md) 中缺失的业务部章节，并为文档尚未定义的 **销货（SHP）、销退（RMA）、报关资料（EXP）** 三块能力给出节点编号、单据字段与状态机。

- 报价（QTN-01/03）、核价（QTN-02）、客户信息（ENG-01）、下单（ORD-01~04）沿用 [报价到全检包装的订单全生命周期](../workflows/order-to-pack-lifecycle.md) 的既有定义，本文只做业务部视角的汇总，不重复正文。
- 标记 **【新增】** 的内容为本轮补充设计，需在评审后回写 Word 基线（V2.2 及以后）并补需求编号。
- 前端实现见 `apps/web/src/pages/sales/`。左侧导航十二项：业务工作台、报价管理（报价单 / 历史报价查询 / 成本核算 / 原材料价格表四个页签）、订单管理（订单列表 / 订单修改申请两个页签）、订单追踪、客户信息管理、BOM 申请、ECN 申请、出货管理、退货管理、对账单、报关资料、数据分析。

## 1. 部门定位与角色

业务部对外承担商务承诺，对内是订单生命周期的发起方与责任方：客户交期承诺由业务发布，PMC 只提供可执行日期与风险，不直接向客户承诺商务条件。

| 角色 | 职责 | 关键权限边界 |
| --- | --- | --- |
| 业务员 | 询价登记、核价牵头、报价送审、客户建档、BOM 申请、建单提交、发起订单评审、客诉登记、报关资料制单 | 不得查看未授权供应商底价；不得修改 HK 价格系数与计算后价格；不得审批本人创建的客户 |
| 业务经理 | ORD-02 订单审核、报价审批、客诉处置方案审批、免费/部分收费必要性确认 | 不得直接改写送审内容，只能批准 / 退回 / 驳回 |
| 业务助理（可选，**【新增】**） | 单据录入、附件整理、发货与报关资料准备、催办跟单 | 只读价格与成本；无提交审批权，仅可保存草稿 |

数据权限：按客户维度隔离，业务员默认只见本人负责客户；越权访问返回 404 而非 403。字段权限在序列化层裁剪，业务角色对客户主数据的银行、税务、信用字段只读或不可见。

| 3b | BOM 申请 | ENG-02 / ENG-05 | 客户资料确认 → 工程回传品号与 BOM | **品号只发给正式订单的产品；样品既无品号也无 BOM，模具建模具编号，备料引用既有品号**；必须关联客户原始资料与已确认报价；同图号同版本重复申请提示；**回传结果必须分别显示「BOM 可下单」与「程序可开工」，不得把程序未完成显示为全部工程完成**；退回记录退回等待时间 |
| 3c | ECN 申请（产品变更） | **ECN-01 ~ ECN-05【新增】** | 客户或内部提出**改图 / 改材料 / 改表面处理** → 新版本发布并批次切换 | 只受理产品本身的变更；改图强制联动改工艺路线，未同步禁止发布；中途改工序只对指定批次版本生效；影响价格或交期强制重新核价并重新走订单审批 |
| 4 | 下单 | ORD-01 ~ ORD-04 | 建单提交（T0） → 跨部门评审结论 | 正式订单零价、缺客户原始订单、缺核价一律阻断；模具/样品免费需四项要素齐全；HK 70% 防重复折算 |
| 4c | 订单修改申请（订单管理页签） | **ORC-01 ~ ORC-05【新增】** | 已生效订单需改订单信息 → 变更批准并同步计划 | 只改订单信息（数量/交期/单价/收费方式/收货信息/包装/取消），不改产品；批准前不得在原订单上静默改写；批准后未同步 PMC 计划的变更持续预警 |
| 5 | 出货管理（销货） | **SHP-01 ~ SHP-06【新增】** | 可发货批次形成（T1） → 商业关闭（回款） | 报关资料未齐套阻断订舱；数量差异需上道确认；尾数必须选定四路径之一 |
| 6 | 退货管理（销退） | **RMA-01 ~ RMA-05【新增】** | 客户投诉/退货登记 → 8D 关闭结案 | 退款、补货、召回、高额索赔升级财务与总经办；责任未判定不得放行处置 |
| 7 | 生成报关资料 | **EXP-01 ~ EXP-04【新增】** | 发货单包装完成 → 关务申报放行 | 申报要素缺失禁止生成；HK 订单不得因客户价格勾选跳过关务复核 |
| 4b | 订单追踪 | **TRK-01 ~ TRK-23【新增】** | 订单评审 → 成品入库 | 23 个环节逐节记录责任部门、计划/实际时间、投入/合格/不良数量与停留时长；**业务部、总经办、PMC 共享同一视图** |
| 6b | 对账单 | **STM-01 ~ STM-05【新增】** | 期间截止 → 客户确认 / 结清 | 期末余额 = 期初 + 本期发货 − 回款 − 退货折让；差异非零必须写明原因，客户确认后金额锁定不可改写 |
| 7b | 发票申请 | **INV-01 ~ INV-04【新增】** | 出货已签收 → 财务开票并交付客户 | 出货单 / 对账单 / 发票三方金额必须一致，不一致一律阻断开票；差异先在对账单处理 |

## 3. 销货 SHP【新增】

### 3.1 节点

| 编号 | 节点 | 责任 | 说明 |
| --- | --- | --- | --- |
| SHP-01 | 生成发货通知 | 业务 | 依据订单与可发批次建单，写入承运方式、交货地点、客户标签要求 |
| SHP-02 | 仓库拣配出库 | 仓储部 | 按批次一码到底拣配，数量差异回写预警 |
| SHP-03 | 全检包装完成（T1） | 后工序部 | 合格数、包装数、订单需求数、差异在同一界面比对 |
| SHP-04 | 出运发货 | 业务 | 出口订单须报关资料齐套后订舱；记录承运商与运单号 |
| SHP-05 | 客户签收 | 业务 | 回传签收单，超期触发预警并阻塞后续开票 |
| SHP-06 | 开票与应收 | 财务部 | 生成应收与回款计划，进入账龄监控 |

### 3.2 单据字段

发货单 `shipments`：`doc_no`、订单号、客户、产品、批次号、订单需求数、合格数、包装数、已发数、尾数、尾数处理路径、包装完成时间、发货时间、签收时间、承运商、运单号、发票号、金额（定点数+币种）、状态、责任人、`version`。

状态机：`planned → picking → packed → shipped → signed → invoiced → closed`，任一状态迁移写 `doc_timeline`。

### 3.3 尾数四路径

`返工补交 / 入库待后续订单 / 直接入库 / 报废`。选定后结案时执行**数量平衡校验**：订单需求数 = 已发数 + 尾数处理数 + 报废数。默认 SLA：尾数处理 7 天、尾数库存保留 90 天（**参数待 ADR 确认，前端不得硬编码，须由配置下发并显示版本**）。

### 4.1 节点

| 编号 | 节点 | 责任 | SLA 建议 |
| --- | --- | --- | --- |
| RMA-01 | 业务登记客诉 / 退货 | 业务 | 首次响应 2 小时 |

| RMA-04 | 退货入库与执行 | 仓储部 / 生产部 | 按处置方案，返工走返工子订单重新核算重复工序成本 |

### 4.2 单据字段

退货单 `sales_returns`：`doc_no`、原订单号、原发货单号、客户、产品、批次号、退货数量、退货原因、责任归属（公司/客户/供应商/待判定）、处置方式（退款/补货/返工/让步接收/报废）、涉及金额、客诉时间、首次响应时间、8D 编号、是否需财务审批、状态、责任人。

状态机：`registered → quality-judging → disposition → executing → closed`，判定不成立走 `rejected`。

成本口径：公司责任的返工不产生对客户的额外应收；供应商责任按无偿返工归集责任毛损失、追偿与企业净损失（沿用 [返工成本归集](../workflows/rework-cost-accounting.md)）。

## 4b. 工程变更 ECN【新增】

### 节点

| 编号 | 节点 | 责任 | 说明 |
| --- | --- | --- | --- |
| ECN-01 | 业务提交变更申请 | 业务 | 登记变更类型、来源（客户/内部）、变更前后值、原因、紧急度、关联订单 |
| ECN-02 | 工程影响评估 | 工程部 | 评估在制工单、已采购物料、已完工库存、已发货批次的影响；**改图必须同步更新工艺路线，否则阻断发布** |
| ECN-03 | 跨部门影响会签 | PMC / 采购 / 生产 / 品质 / 财务 | 评估交期、采购、成本与质量影响 |
| ECN-04 | 变更批准与版本发布 | 工程部 →（重大变更）总经办 | 发布新图纸版本、BOM 版本与工艺路线版本 |
| ECN-05 | 执行与批次切换 | PMC / 生产 | 指定生效批次版本；旧版本在制与库存按处置结论执行 |

### 单据字段

`bom_requests` 中 `production_type` 只有 `batch`（正式量产，建品号）与 `mold`（模具，建模具编号）两个取值，样品不进入该表；`from_sample_no` 记录由样品转量产时的来源样品单号。

`engineering_changes`：`doc_no`、客户、关联订单、产品、图号、变更类型（图纸版本 / 材料牌号 / 表面处理 / 工艺工序——仅此四类）、变更来源、紧急度、变更前值、变更后值、变更原因、影响范围明细（范围/数量/金额/处置说明）、工艺路线是否已同步、生效批次、是否触发重新核价、是否触发订单重新审批、状态、责任人。

状态机：`draft → submitted → assessing → reviewing → approved → executing → closed`，驳回走 `rejected`。

### 强制规则

1. 变更类型为「图纸版本」时，工艺路线未同步更新一律禁止批准发布。
2. 变更类型为「工艺 / 工序」时必须指定生效批次版本，已投产批次沿用原路线并保留版本号，不追溯已发货批次。
3. 变更影响价格、数量或交期时，系统自动置「触发重新核价」与「触发订单重新审批」，走订单变更流程，不允许在原订单上静默改写。
4. 变更的影响评估必须覆盖四个范围：在制工单、已采购物料、已完工库存、已发货批次，金额计入相应责任方。
5. **ECN 只受理产品变更**：改图纸、改材料、改表面处理，以及由此必须同步的工艺路线。数量、交期、单价、收费方式、收货信息、包装要求与取消订单属于**订单信息变更**，一律走「订单管理 → 订单修改申请（ORC）」，两条流程不得互相替代，避免同一诉求在两处各批一次、互相覆盖。

## 4b-2. 订单修改申请 ORC【新增】

### 定位

ECN 改的是「产品是什么」，ORC 改的是「这张订单怎么执行」。判断口径只有一条：**图纸、材料、表面处理动了就是 ECN，其余动的都是 ORC。**

| 变更内容 | 走哪条流程 |
| --- | --- |
| 图纸版本、材料牌号、表面处理、随图同步的工艺路线 | ECN 申请 |
| 数量、交期、单价 / 金额、收费方式、收货信息、包装要求、取消订单 | 订单修改申请 ORC |

### 节点

| 编号 | 节点 | 责任 | 说明 |
| --- | --- | --- | --- |
| ORC-01 | 业务提交订单修改申请 | 业务 | 登记变更类型、来源（客户/内部）、变更前后值、原因、紧急度、费用承担方 |
| ORC-02 | PMC 产能与交期评估 | PMC 部 | 评估在制工单、排产、采购与新交期可达性 |
| ORC-03 | 财务重新核价与信用复核 | 财务部 | 数量变动触发阶梯价重算；调价需复核毛利与信用额度 |
| ORC-04 | 订单重新审批 | 业务经理 →（重大变更）总经办 | 订单回到 ORD-02 重走审批链，原审批结论作废 |
| ORC-05 | 执行与计划同步 | PMC / 采购 / 后工序 | 同步排产、采购与包装要求；未同步前订单追踪按原交期继续预警 |

### 强制规则

1. 已生效订单的数量、交期、单价一律不得直接改写，必须经 ORC 批准后由系统回写，并保留变更前值。
2. 涉及取消订单时，已发生成本必须逐项列示并指定承担方，客户承担的部分开票收取。
3. 调价只调**原价**，HK 70% 系数由系统计算，禁止手工先折算后录入（沿用 ORD_25xx 规则）。
4. 已出货部分按原价结算不追溯，未出货部分按新价执行，对账单按两段单价分行列示。
5. 批准后 `planSynced` 为假的变更在工作台持续预警，直至 PMC 回写同步结果。

## 4b-3. 品号与 BOM 的适用范围【新增】

**品号（产品编码）只发给正式订单的产品。** 这是一条主数据层面的硬规则：品号代表「本厂已正式量产、可重复接单的产品」，一次性试做与工装不占用品号空间。

| 订单类型 | 品号 | BOM 与工艺路线 | 标识方式 |
| --- | --- | --- | --- |
| 正式业务订单 | **有**，由工程在 BOM 申请中建立 | 正式 BOM + 工艺路线，双状态回传 | 品号 + 图号版本 |
| 样品订单 | **无** | **不建 BOM**，只编制临时工艺路线 | 图号 + 样品单号 |
| 模具订单 | **无**（模具不是可售产品） | 模具 BOM 与加工路线 | **模具编号** |
| 备料订单 | **引用已有品号**，不新建 | 沿用该品号已发布的 BOM | 品号 + 备料单号 |

1. 样品按客户来图直接编制**临时工艺路线**试做，不建品号、不建 BOM，也不做「程序可开工」确认，避免为一次性试做占用工程资源与主数据空间。
2. 样品转量产时，由业务提交 BOM 申请，工程此时才建立**品号、BOM 与工艺路线**，并**回填对应样品单号**，把试做工时与实际成本带入首次量产的成本参考值。
3. 备料订单必须引用该图号**已量产的品号**；若该产品尚未正式量产（无品号），不允许开备料订单——否则会出现「为一个还不存在的产品备库存」。
4. 模具订单建的是**模具编号**，与品号分属两套编码，不得混用；模具编号在 BOM 申请中以「模具」用途申请。
5. 建单阻断校验按订单类型分支：
   - 样品订单：显示「样品订单免品号、免 BOM」并直接通过；
   - 备料订单：必须填写引用的既有品号；
   - 正式订单：必须有品号**且**关联回传「BOM 可下单」的申请单号（「程序可开工」是另一状态，不得合并判定）；
   - 模具订单：必须有模具编号。

## 4c. 备料订单与加权平均成本【新增】

订单类型在模具 / 样品 / 正式之外新增**备料订单**：

1. 备料订单**不向客户交货**，不产生客户应收（收费方式固定为「内部备料」），但**全额核算生产成本**。
2. 备料订单完工后**全部入库即视为订单完成**（`stockedQty` 达到订单数量），库存进入备料余量池。
3. 正式业务订单可**关联同图号的备料订单**领用余量，领用后余量自动扣减，扣完关闭该备料订单。
4. 成本口径：领用部分按备料订单的单件生产成本计价，其余按新投产成本计价，订单成本取**加权平均**：

```text
加权平均单件成本 = (备料单件成本 × 领用数量 + 新产单件成本 × 新投产数量) ÷ 订单数量
例：订单 100 件，备料余 20 件（单件 10 元），新投产 80 件（单件 12 元）
    → (10 × 20 + 12 × 80) ÷ 100 = 11.60 元/件
```

界面上三段并排显示「领用备料 × 单价 + 新投产 × 单价 = 加权平均成本」，并给出计算式；未录入新产单件成本时阻断提交。

## 4d. 订单追踪 TRK【新增】

从**订单评审**开始追踪到**成品入库**，共 23 个环节，分五个阶段：

| 阶段 | 环节 |
| --- | --- |
| 计划与采购 | 订单评审 → PMC 跑生产计划 → 采购计划 |
| 来料与检验 | 到料 → 原材料品质检（IQC） |
| 机加工 | 切料 → 调机 → 首件检测 → 车床 → 品质检 → CNC → 品质检 |
| 后处理与委外 | 打磨 → 品质检 → 仓库（委外前入库）→ 委外表面处理 → 仓库（回厂入库）→ 品质检 → 镭雕丝印 → 品质检 |
| 交付入库 | 包装 → 出货报告 → 入库 |

### 呈现方式：工单进度条

主视图为**工单进度条**——一张订单一行，23 个环节自左向右串成一条圆点链：

| 圆点样式 | 含义 |
| --- | --- |
| 灰圈 + 「0%」 | 未开始 |
| 蓝底 + 圈内百分比 | 进行中，百分比为该环节的完成度（优先取环节自带值，其次按合格数/投入数推算） |
| 绿底 + 对勾 | 已完成 |
| 蓝底 + 右上角红角标 | 受阻 / 异常，环节名同时标红 |

行首汇总订单号、订单类型、客户、产品图号、批次、数量、交期与风险标签，行尾给出整单完成度百分比（已完成环节数 + 当前环节完成比例）与「x / 23 环节」。鼠标悬停任一圆点显示该环节的责任部门、实际起止时间、投入 / 合格 / 不良数量、停留时长与备注；点击圆点或整行展开按五个阶段分组的完整明细。另提供「明细表」视图供筛选与导出。

每个环节记录：责任部门、状态（已完成 / 进行中 / 未开始 / 受阻）、完成百分比、计划与实际起止时间、投入 / 合格 / 不良数量、停留时长与备注。

**可见范围：业务部、总经办、PMC 三方共享同一视图**（数据权限按各自的数据范围过滤，但环节口径一致）。交付风险分正常 / 临期 / 已延期三级，受阻环节标红并写明阻塞原因。

## 7a. 历史报价的工序级成本回溯

历史报价查询的每一行可打开「详情 / 回溯」抽屉，按四块展示：

1. **当时的报价**：报价日期、业务员、客户、产品图号材质表面处理、数量、单价、报价单位成本、报价单件毛利、报价毛利率、实际毛利率、强制关联的成本分析单号、实际成本来源订单。
2. **当时的成本分析（按工序预估）**：核价单的工序展开，逐道工序独立核算，字段为工序号、工序名、机台或委外供应商、分项归属（材料 / 加工时间 / 工艺）、标准工时、单件成本、成本占比、转入累计、转出累计。转出累计为该工序完工时的单件累计成本，用于判断价值在哪一道工序形成。
3. **实际成本回溯（按工序实际）**：实际成本取自生产订单的工序报工、领料与委外对账，与报价假设逐道对照，字段为转入累计、报价成本、实际成本、偏差与偏差率、标准 vs 实际工时、工时偏差、转出累计、偏差原因。单道工序偏差 ≥ ±5% 进入报价成本偏差分析并推送报价工程师。领用备料的订单额外显示加权平均口径说明。
4. **分项汇总与结论**：材料 / 加工时间 / 工艺三项各自的报价、实际、偏差与占比，加单件合计；合计偏差超过 ±5% 时该产品的成本参考值需回写修正后方可用于新报价。

未成交或未投产的报价只展示第 1、2 块，实际成本列显示「—」而非 0，避免把未投产误算成零成本。早期未做工序拆分的报价单在抽屉内给出空状态说明。

数据契约见 `apps/web/src/types/sales.types.ts` 的 `OperationCostLine`（seq / operation / workCenter / element / stdMinutes / actMinutes / quotedCost / actualCost / note），累计值由前端按工序顺序推算，不落库。

## 9. 本轮新增的硬性规则（第五轮评审）

### 9.1 品牌

1. **公司 LOGO 不得改色**，界面、导出件与截图一律保持原始 VI 配色；详见 `docs/design/brand-logo.md`。截图打包禁止调色板量化压缩。

### 9.2 权限

2. **香港 70% 价格设定只有业务部权限可见**（权限码 `sales.hk-price.view`）。无权限的业务员只看到系统计算后的订单单价与金额，看不到原价、系数与折算过程。
3. **成本核算只有报价工程师可以做**（权限码 `quote.costing.edit`）。其他角色进入「成本核算」页签为只读，成本项与报价单价不可编辑，也不能保存核价版本。

### 9.3 报价

4. **报价申请由业务发起，只提供图纸与数量**（数量可阶梯、可非阶梯）；材料牌号、表面处理、工艺路线、工时假设、成本分析与最终单价一律由报价工程师补齐。报价单因此新增阶段字段：`applied`（待工程师补齐）→ `costing`（核价中）→ `quoted`（已报出）→ `confirmed`（客户已确认）。
5. **报价单强制上传图纸**。图纸上传后由系统同时分发给报价工程师（用于报价）与工程部（用于建立 BOM），分发清单记录在图纸附件上，未上传图纸不得提交报价申请。
6. **报价单修改申请（QRC）**：业务不直接改报价单，而是提交修改后的价格与理由；报价工程师复核后要么按新价重做成本分析并回写（报价单升版），要么**驳回并填写驳回理由**（不少于 10 个字，同步业务与业务经理）。成本分析始终只由报价工程师维护。
7. 报价单与成本分析表均可**导出 Excel**，并支持**多选合并导出**到同一张报价单 / 成本分析表，用于给客户发一份含多个产品的总报价，或横向对比多份核价。成本分析导出时，受字段权限保护的供应商底价导出为 `***`，导出不绕过字段级权限。

### 9.4 订单

8. **下单前工程资料齐套校验**：产品缺少报价单、成本分析、品号、BOM、图纸中的任意一项，一律提示错误并禁止下单；样品订单免品号与 BOM，不受此约束。
9. **客户交期为必填项**（备料订单对应「期望完工日」，同样必填）。
10. **客户订单原件强制上传**：模具订单与正式业务订单一律要求；样品订单只要收费也必须上传，免费样品可豁免。
11. **一张单可以下多项产品**：订单、出货单、退货单均改为明细行结构（`lines`），每行独立记录产品、图号、品号、数量、单价、金额与行交期；单产品单据同样写一行，口径统一。
12. **订单修改申请不得修改价格与下单产品**。改价走报价单修改申请（QRC）由报价工程师处理；换产品等于换一张订单，须取消原单重下；改图纸 / 材料 / 表面处理走 ECN。ORC 可改范围收敛为：数量、交期、收货信息、包装要求、取消订单。

### 9.5 追踪与报表

13. **工单进度条圆圈内显示「完成数 / 工单数」**（如 58 / 100），不再显示百分比。工单数取该环节投入数（未投入时取订单数量），完成数取该环节合格数。
14. **所有表格可下载**：列表页筛选条上统一提供「导出 Excel」（导出当前筛选结果，并把生效的筛选条件写入表头说明）；数据分析每张报表卡片右上角提供「下载」，页面顶部提供「导出全部报表」（一张报表一个工作表）。

### 9.6 发票申请 INV【新增】

| 编号 | 节点 | 责任 | 说明 |
| --- | --- | --- | --- |
| INV-01 | 业务提交发票申请 | 业务 | 按已签收出货单归集开票行，填写抬头、税号、开户行、地址电话与交付方式 |
| INV-02 | 金额三方一致性校验 | 系统 | 出货单金额、对账单金额与申请开票金额必须完全一致，不一致直接阻断 |
| INV-03 | 财务开票并回写发票号 | 财务部 | 开具专票 / 普票 / 出口发票 / 形式发票，回写发票号与开票时间 |
| INV-04 | 交付客户并进入应收账龄 | 业务部 | 电子发票发邮箱、纸质发票走快递；开票日起进入应收账龄与回款预警 |

强制规则：三方金额不一致禁止提交财务开票，差异必须先在对账单完成挂账、红字或折让处理，避免开票后再作废红冲；出口业务按零税率开形式发票，外币按开票日中行中间价锁定汇率并写入对账单。

### 9.7 数据分析全量可导出（补充）

15. **数据分析的每一张报表都可导出 Excel**：报表卡片右上角「下载」导出该表（列头按字段中文映射，口径写进表头说明）；「经营总览」的图表卡片同样可下载其底层数据（月度趋势、客户 Top 5、订单结构、转化漏斗、客户毛利对照、指标口径表）；页面顶部「导出全部报表」把全部报表一次导出为一个工作簿，一张报表一个工作表（当前 48 个工作表）。
16. 导出统一走 Blob + `a[download]`，保证中文文件名与 `.xlsx` 扩展名正确；文件名带导出时间戳便于归档追溯。

### 9.8 账户申请（AUTH）【新增】

登录页新增「申请账户」入口（仅内部员工域显示，客户 / 供应商门户账号由业务对接人代开）。

| 字段 | 规则 |
| --- | --- |
| 员工姓名 | 必填，与身份证 / 工牌一致 |
| 所属部门 | 必填，从十二个部门中选择 |
| 用户名 | 必填，**全公司唯一编码**；4–20 位、字母开头，只允许小写字母、数字、点与下划线；开通后不可修改 |
| 密码 / 确认密码 | 必填，至少 8 位，两次必须一致；界面给出四档强度提示 |
| 联系方式 / 申请说明 | 选填，便于 IT 核实身份 |

唯一性规则：

1. 用户名输入后失焦或点「检查可用性」即时校验，冲突时给出原因与三个可用建议（点击即填入）。
2. **已提交但尚未审批的申请同样占用该用户名**，避免两个人同时申请到同一个编码。
3. 前端的即时校验只是提前提示，**提交时服务端再校验一次**并以服务端结果为准（AUTH_1022 用户名已被占用）；被抢占时前端会自动刷新可用性提示。
4. 错误码：AUTH_1020 必填缺失、AUTH_1021 用户名格式非法、AUTH_1022 用户名已占用、AUTH_1023 密码长度不足、AUTH_1024 两次密码不一致。

提交后生成申请单号 `ACR + yyyyMMdd + 4 位流水`，派单至信息部 IT 系统管理员：核实在职状态与部门归属后开通，角色与数据范围由部门负责人确认，开通结果通过企业微信通知本人。

### 9.9 每日经营量（补充报表）

数据分析「经营总览」页签置顶新增一张 **每日经营量：接单 / 出货 / 未完成订单**（可切近 7 / 14 / 30 天，可单独下载）：

| 指标 | 性质 | 口径 |
| --- | --- | --- |
| 当日接单量 | 流量 | 当日 ORD-02 审核通过的订单，按张数、件数与合同金额统计；备料订单件数计入、金额按预计生产成本计 |
| 当日出货量 | 流量 | 当日实际发货（SHP-04）的发货单，按张数、件数与出货金额统计 |
| 未完成订单量 | **存量** | 截至当日日终，已评审通过但尚未全部出货的订单，按张数、未交件数与未交金额统计 |

三者的勾稽关系写在卡片口径里：**昨日存量 + 今日接单 − 今日出货 = 今日存量**。卡片同时给出区间合计、工作日日均，以及「净流入 = 接单 − 出货」——为正说明在手订单在累积（要盯产能与交期），为负说明产出快于接单。图形上接单与出货用双柱（流量），未完成订单用折线（存量）叠加，避免把存量与流量画成同一种量纲。周日不排产，接单与出货为 0、存量保持不变。

### 9.10 用户名与唯一编码（修订）

**用户名不是唯一编码。** 两者职责分开：

| | 用户名 | 唯一编码 |
| --- | --- | --- |
| 用途 | **仅用于登录** | 系统内的用户身份标识 |
| 生成方式 | 员工自己登记 | **每次注册时由系统单独生成**（`WFX-年份-4 位流水`） |
| 唯一性 | 在职期间不可重复 | 全局唯一 |
| 离职后 | **释放**，可由他人再次登记 | **不释放、永不复用** |
| 可否修改 | 按 IT 流程可改 | 终身不变 |
| 被谁引用 | 登录页 | **所有单据、审批、留痕、责任人字段一律关联唯一编码** |

规则：

1. 注册时系统即生成唯一编码，编码流水只增不减，已发放的编码任何情况下都不回收。
2. 用户名在职期间不可重复，已提交待审批的登记同样占用；员工离职后用户名释放，他人可再次登记。
3. 登记一个曾被离职员工使用过的用户名时，界面以橙色提示原使用人与离职日期，并说明**本次注册会另行生成新的唯一编码，与原使用人无关**，不继承其角色、数据范围与待办。
4. **离职账号本身停用**，不能再登录（AUTH_1030）；释放的只是用户名。
5. 因为单据关联的是唯一编码而不是用户名，用户名换人**不会影响任何历史数据**——这正是把两者拆开的原因：登录名可以复用，身份标识不能。
6. 界面上，顶部用户区显示「部门 · 唯一编码」，悬停可看到完整的编码与登录用户名对照。

错误码：AUTH_1020 必填缺失、AUTH_1021 用户名格式非法、AUTH_1022 用户名已被占用、AUTH_1023 密码长度不足、AUTH_1024 两次密码不一致、AUTH_1030 账号持有人已离职、账号停用。
