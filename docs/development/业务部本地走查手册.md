> 面向：要在自己电脑上把**业务部十三个功能**跑起来、点一遍、给人演示的任何人。

## 一、先决条件

只需要两样：

| | 版本 | 怎么确认 |
| --- | --- | --- |
| Node.js | ≥ 20.11（实测 22） | `node -v` |

### 4. 新建业务订单 `/sales/orders/create` · ORD-01

这一页专门用来演示**两条最容易被误解的规则**：

- **订单类型与收费方式是两个独立字段**。选「模具」或「样品」**不等于**自动免费；选「正式业务订单」则强制收费。
- **免费也必须完整核算成本**。

**走查动作**：把订单类型在「正式业务订单 / 模具订单 / 样品订单 / 备料订单」之间切换，观察价格区块的标题在「三、价格」与「四、价格」之间变化，以及收费方式是否被强制。

再试一次**故意留空**：正式业务订单不填价格直接提交，应被拦下并显示中文原因（零价、缺原始订单、缺核价三种之一）。**服务端文案原样显示，不会被换成「操作失败」**——那句话本身才是用户需要的信息。

### 5. 订单追踪 `/sales/tracking` · TRK-01 ~ TRK-23

**这一页不是表格，是进度条**，两个页签：「工单进度条」与「明细表」。

一张订单一行，**23 个环节从左到右依次点亮**。圈内是「完成数 / 工单数」（如 `58 / 100`，上为该环节合格数、下为投入数）：

- 灰圈 = 未开始
- 蓝圈 = 进行中
- 绿圈 = 已完成
- 红角标 = 受阻

**走查动作**：鼠标悬停任一环节，看责任部门、起止时间、投入/合格/不良数量与停留时长；点任一环节或整行，展开 23 环节完整明细。顶部有「导出追踪报表」。

可见范围写在页面上：业务部 · 总经办 · PMC。

### 8. ECN 申请 `/sales/ecn` · ECN-01 ~ ECN-05 ★重点

四张单，覆盖了本轮新增的**生产影响分类**规则：

| 单号 | 状态 | 生产影响 | 用来演示 |
| --- | --- | --- | --- |
| ECN-20260727-0018 加急 | 评估中 | 未判定 | 改图未同步工艺路线被拦 |
| **ECN-20260720-0015** | 已批准 | **有影响**（尚未清点） | **完整的清点 → 返工 → 结案闸门** |
| ECN-20260716-0012 | 执行中 | **无影响** | 无影响路径整段跳过 |
| ECN-20260728-0019 | 草稿 | — | 建单 |

#### 完整走一遍「有影响」的链路（推荐照这个顺序点）

打开 **ECN-20260720-0015**，抽屉里能看到「对生产有影响」红色标签，以及「受影响数量（PMC 清点）」区块显示**尚未清点**。

1. 点 **转入执行** → 提示「已转入执行与批次切换」
2. 直接点 **结案** → **被拦**，提示「对生产有影响的变更必须先由 PMC 录入受影响数量」
3. 点 **录入受影响数量** → 弹窗顶部写着计数口径：
   > **只要生产（车床/CNC）动了，就计入受影响数量**；尚未上机的料不计。
   填「已投产数量」`1000`，备注「已切料 1000 件为 304」，保存
4. 再点 **结案** → **又被拦**，提示「对生产有影响的变更必须先发起返工才能结案」
5. 点 **发起返工** → 二次确认框：「发起返工后，本单的受影响数量将被锁定，不可再修改」→ 确认发起
6. 观察：抽屉里出现橙色一行「返工已于 … 发起，受影响数量已锁死」，**「录入受影响数量」和「发起返工」两个按钮消失**
7. 再点 **结案** → **放行**，提示「变更已结案」

#### 对照「无影响」的路径

打开 **ECN-20260716-0012**：标签是「对生产无影响」，**整个清点区块不出现**，直接点结案即放行。

> 这一对照是刻意做的：让无影响的变更去录一个 0，只会让真正需要清点的那些混在里面看不出来。

#### 边界提示

页面顶部常驻橙色条：**改数量 / 改交期 / 改价格不走 ECN**——那些走订单修改申请（ORC）或报价单修改申请（QRC）。填错类型提交，服务端会**点名正确去处**，而不是只说「不受理」。

### 10. 退货管理 `/sales/returns` · RMA-01 ~ RMA-05

**走查动作**：点「详情」→ 底部「关联 8D 报告」「提交处置方案」。

**看点是逐行判定**：责任（我方 / 客户 / 供应商 / 未定）与处置（返工 / 报废 / 让步 / 退款）是**每一行独立判**的，单头只是派生视图——全行一致才取该值，**不一致时单头回落「未定」并单独标记「责任不一致 / 处置不一致」**，而不是挑一行冒充全单。

| 2 | 定位销座 MT-7420 | 30 | 供应商 | 退款 |

## 四、一次完整的端到端演示脚本（约 10 分钟）

给老板或业务演示时按这条线走，能把业务部的骨架串起来：

1. **客户信息管理** — 打开 C0001，指出信用占用与职责分离
2. **报价管理** — QT-20260722-0031 V2，点「出具报价单」，指出版本号只升不改
3. **新建业务订单** — 切订单类型，演示「模具 ≠ 免费」，再故意留空价格被拦
4. **BOM 申请** — BOM-20260722-0039，指出「BOM 可下单」与「程序可开工」是两个状态
5. **ECN 申请** — 走第 8 节那七步完整链路（**全场最有说服力的一段**：连拦两次，补齐才放行）
6. **订单追踪** — 23 环节进度条，悬停看某环节的投入/合格/停留时长
7. **出货管理** — SHP-20260727-0064 的「14 返工补交」，点尾数处理
8. **对账单 → 发票申请** — 指出三方金额不一致被阻断
9. **报关资料** — 要素不齐时生成被拦，补齐后出五个文件
10. **数据分析** — 「查看数据表」翻口径，并说明桩位为什么给空不给零

**贯穿全场的一句话**：页面上的禁用只是提前提示，**真正的闸门在服务端**，而且服务端的中文错误原样端到用户面前——那句话才是用户需要的信息。

```bash
cp infra/.env.example infra/.env
cp services/api/.env.example services/api/.env
pnpm stack:up        # Postgres + Redis + MinIO + 建桶 + kkFileView
pnpm db:migrate
pnpm db:seed
pnpm dev:api         # http://localhost:3000/api/v1，Swagger 在 /api/v1/docs

cp apps/web/.env.example apps/web/.env.development   # 把 VITE_USE_MOCK 改成 false
pnpm dev:web
```

### 这条路径上已知会绊人的三处

1. **`unknown shorthand flag: 'f' in -f`** — Docker CLI 没装 compose 插件，`compose` 没被识别成子命令才把 `-f` 当顶层 flag。
2. **`docker-credential-desktop ... not found`** — `~/.docker/config.json` 里残留 Docker Desktop 时代的 `"credsStore": "desktop"`。本项目全是公共镜像，删掉该键即可。
3. **`pnpm install` 提示 `The "pnpm" field in package.json is no longer read`** — 已修（配置搬到了 `pnpm-workspace.yaml`）。若仍看到，说明本地是旧版本，`git pull` 一下。

三处的具体命令见 [本地运行手册第五节](local-run.md#五跑不起来时按这个顺序查)。

> **迁移落后于 schema 三批**：docgen、ecn-request、生产影响分类还没有对应迁移。
> `pnpm db:migrate` 会生成补齐，**生成完记得提交进仓库**——生产的 `migrate deploy` 只认仓库里的迁移文件。

## 六、走查时如果不对劲

| 现象 | 多半是 |
| --- | --- |
| 页面能开，但点按钮毫无反应 | 走的是打包产物且没带 `VITE_USE_MOCK=true`；或切了 `false` 但后端没起 |
| 登录点了没动静 | 同上；开发态 `pnpm dev:web` 不会有这个问题 |
| 某个流转按钮点了没变化 | 先看右上角有没有一闪而过的中文提示——闸门拦截也是提示，不是「没反应」 |
| 数据被我点乱了 | mock 数据是内存态，**刷新页面（F5）即全部复原** |
| 5173 端口被占 | `pnpm dev:web -- --port 5174` |

最后一条值得单独强调：**走查随便点，点坏了刷新就回来了。** 不用担心把演示数据搞乱。
