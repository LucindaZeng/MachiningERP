# 跨工序返工流程

## 业务问题

第五工序发现第二工序质量问题后，不能把“退回第二工序”理解成一个简单状态。返工可能产生两种完全不同的后续路线，系统必须由质量、工程和生产受控判定。

## 路线 A：返工后直接返回第五工序

```mermaid
flowchart LR
    O5[第五工序发现问题] --> F[冻结受影响数量]
    F --> R[MRB评审]
    R --> O2[第二工序返工]
    O2 --> Q[返工复检]
    Q --> O5R[返回第五工序]
```

适用条件：第二工序返工不改变第三、第四工序已经确认的尺寸、基准、表面、装配或其他质量特性。第三、第四工序原履历继续有效，但必须有有效性确认依据。

## 路线 B：返工后从第三工序顺序重流

```mermaid
flowchart LR
    O5[第五工序发现问题] --> F[冻结受影响数量]
    F --> R[MRB评审]
    R --> O2[第二工序返工]
    O2 --> Q2[第二工序复检]
    Q2 --> O3[第三工序重新执行]
    O3 --> O4[第四工序重新执行]
    O4 --> O5R[第五工序重新执行]
```

适用条件：第二工序返工使第三、第四工序原结果失效。系统必须阻止直接跳回第五工序；第三、第四工序原履历保留并标记为被新返工路线替代。

## 同批数量拆分

同一异常批次可以将不同数量分配到路线 A 和路线 B。系统必须：

- 生成子批次和独立二维码；
- 分别记录在制位置、当前工序、计划、材料、工时、检验和成本；
- 未达到各自复检和汇合条件前禁止混批；
- 最终能从原批次追溯全部子批次和路线。

## 状态建议

`Detected → Frozen → MRB Pending → Route Approved → Returned → Reworking → Reinspection → Reflowing/Return Pending → Released → Closed`

每次状态变化记录操作者、时间、数量、位置、原因、前后状态和批准人。

## 核心数据

- 原订单、工单、批次/序列号、原路线版本和发现工序；
- 责任工序、缺陷、实测值、图片、影响特性和受影响数量；
- 返工起点、路线类型、重做工序、保留工序、失效工序和复检项目；
- 子批次、二维码、返回节点、汇合条件和顺序约束；
- 返工材料、补料、人员、设备、刀具、工装、委外、检验和物流；
- 原计划、重排计划、预计完工、客户交期和预警；
- 原成本、新增成本、被替代成本、质量损失和责任归属。

## 控制规则

1. 操作人员不能自行选择路线、返回节点或解除冻结。
2. 工程变更产生新路线版本，不能覆盖原路线。
3. 路线 B 的每道重流工序均需扫码、报工和规定检验。
4. 部分合格时按数量继续拆分，不能把整批直接标记完成。
5. 返工同步更新 MRP 补料、APS 负荷、工序进度、成本、一次合格率和交期风险。

## 验收

- 路线 A、路线 B 和同批拆分三个案例全部通过；
- 原履历、被替代履历和新履历可同时查询；
- 尝试跳过重流工序时系统阻止并记录；
- 数量、在制、成本、良率和预计交期在各模块一致；
- 系统生成跨工序返工路线与成本分析报告。
