# ADR-0001：仓库与架构基线

- 状态：Accepted
- 日期：2026-07-10

## 背景

项目已经形成跨 ERP、PLM、APS、MES、QMS、WMS、门户、BI、AI 和外部行情的详细需求，但尚未完成厂商与技术栈选型。立即生成具体框架代码会提前锁定架构并增加重做成本。

## 决策

1. 当前仓库先建立产品、架构、流程、治理、Issue/PR 和自动检查基线。
2. 采用 `apps/`、`services/`、`packages/`、`infra/` 和 `tests/` 的技术中立目录边界。
3. 技术栈、数据库、部署和服务拆分必须通过后续 ADR 决定。
4. 首个实现采用真实脱敏订单的垂直切片，而不是一次铺开全部模块。
5. 核心业务使用稳定需求编号，Word 方案和 GitHub 交付保持可追溯。
6. 在确认确有独立扩展、部署或隔离需要前，不把每个 ERP 模块都拆成微服务。

## 结果

优点：降低过早技术承诺，便于 ERP 采购与自研混合路线，研发工作有统一入口和质量门。

代价：仓库当前不能直接启动应用；下一阶段必须完成技术选型 ADR 和首个垂直切片设计。
